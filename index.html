2. Exemples de QCM

Exemple 1 — Module 02

Quelle commande lance le serveur en mode développement avec nodemon, si le script dev est défini dans package.json ?

a) npm start   b) npm run dev   c) node dev   d) npm i dev

Voir la réponse

b) npm run dev lance le script dev défini dans package.json.

Exemple 2 — Module 03

Quel code de statut indique que la requête est mal formée ?

a) 201   b) 400   c) 404   d) 500

Voir la réponse

b) 400 (Bad Request) : requête malformée ou invalide.

Exemple 3 — Module 04

Quelle propriété de l'objet retourné par fetch() contient le code de statut HTTP ?

a) response.body   b) response.status   c) response.type   d) response.headers

Voir la réponse

b) response.status contient le code (ex. 200, 404). response.ok est vrai pour les codes 2xx.

3. Exemples de questions d'explication

Exemple A — PUT et PATCH (avec un exemple)

Un utilisateur possède ce profil dans la base de données :

{ "nom": "Ali", "courriel": "ali@exemple.com", "age": 20 }

Il veut seulement changer son âge à 21. Expliquez la différence entre une requête PUT et une requête PATCH pour faire ce changement, et dites laquelle vous choisiriez.

Voir une réponse attendue

PUT remplace la ressource au complet. Il faut donc envoyer tout le profil, avec nom, courriel et age: 21. Si on n'envoie que l'âge, les autres champs risquent d'être perdus.

PATCH ne modifie que les champs envoyés. On envoie seulement { "age": 21 } et le reste du profil ne change pas.

Choix : PATCH, car on ne modifie qu'un seul champ et on n'a pas besoin de renvoyer tout le profil.

Exemple B — Module 01

Dans une fonction async, que se passe-t-il si on oublie le mot-clé await devant un appel à une fonction qui retourne une promesse ? Donnez un exemple de ce qui peut arriver.

Voir une réponse attendue

La variable contient la promesse elle-même, et non la valeur attendue. Par exemple, texte.toUpperCase() peut échouer, ou un console.log affiche Promise { <pending> } au lieu du contenu du fichier.

4. Exemple de question de programmation en plusieurs étapes

Le problème suivant a la même forme que ceux de l'examen : il est découpé en étapes. Vous devez écrire le code complet de chaque étape.

Problème — Liste de chansons

Étape 1 — Couche de données (model/chansons.js). Écrivez un tableau privé de chansons (chaque chanson est une chaîne de caractères), et exportez quatre fonctions :

  • getChansons() : retourne le tableau.
  • addChanson(titre) : ajoute une chanson à la fin.
  • updateChanson(index, titre) : remplace la chanson à la position index.
  • deleteChanson(index) : supprime la chanson à la position index.

Étape 2 — Routes (server.js). Écrivez les routes suivantes, en utilisant les fonctions de l'étape 1 :

  • GET /api/chansons : retourne la liste (code 200).
  • POST /api/chansons : ajoute le titre envoyé dans le corps (code 201).
  • PUT /api/chansons : modifie la chanson dont la position et le nouveau titre sont dans le corps (code 200).
  • DELETE /api/chansons : supprime la chanson dont la position est dans le corps (code 200).

Étape 3 — Partie créative. Ajoutez une route de votre choix, utile pour une liste de chansons (par exemple, compter les chansons, ou chercher une chanson par son titre). Expliquez en une phrase ce que fait votre route et le code de statut que vous retournez.

Voir la solution de référence (étapes 1 et 2) 
// model/chansons.js
let chansons = [];

export function getChansons() {
    return chansons;
}

export function addChanson(titre) {
    chansons.push(titre);
}

export function updateChanson(index, titre) {
    chansons[index] = titre;
}

export function deleteChanson(index) {
    chansons.splice(index, 1);
}

// server.js
import 'dotenv/config';
import express, { json } from 'express';
import { getChansons, addChanson, updateChanson, deleteChanson } from './model/chansons.js';

const app = express();
app.use(json());

app.get('/api/chansons', (request, response) => {
    response.status(200).json(getChansons());
});

app.post('/api/chansons', (request, response) => {
    addChanson(request.body.titre);
    response.status(201).end();
});

app.put('/api/chansons', (request, response) => {
    updateChanson(request.body.index, request.body.titre);
    response.status(200).end();
});

app.delete('/api/chansons', (request, response) => {
    deleteChanson(request.body.index);
    response.status(200).end();
});

app.listen(process.env.PORT);

5. Conseils de révision

  • Refaites les exemples du cours sans les copier : c'est ce qui vous prépare aux problèmes nouveaux.
  • Pour chaque route, demandez-vous : quelle méthode HTTP, quel chemin, où sont les données (query ou body), et quel code de statut ?
  • Pour les explications, donnez toujours un exemple concret quand la question le demande.
  • Lisez votre code à voix haute : si vous ne pouvez pas expliquer une ligne, revoyez la notion.
