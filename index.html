Groupe 0090

A. QCM (exemples)

1. Quelle ligne importe la fonction readFile depuis le module de fichiers qui retourne des promesses ?

a) import { readFile } from 'node:fs/promises';
b) const readFile = require('fs');
c) import { readFile } from 'node:path';
d) import readFile from 'readline';

Voir la réponse

a) node:fs/promises fournit des versions qui retournent des promesses. Le require est du CommonJS, interdit dans ce cours.

2. Dans quel fichier sont listées les dépendances d'un projet Node.js ?

a) server.js   b) .gitignore   c) package.json   d) index.html

Voir la réponse

c) package.json, dans la section dependencies.

3. Que fait la ligne import 'dotenv/config'; au début de server.js ?

a) Elle crée le serveur.   b) Elle charge les variables du fichier .env.   c) Elle installe les paquets.   d) Elle ferme le serveur.

Voir la réponse

b) Elle charge les variables du fichier .env dans process.env, d'où l'importance de la mettre au début.

4. Quel code de statut signifie « non autorisé, authentification requise » ?

a) 200   b) 401   c) 301   d) 500

Voir la réponse

b) 401 (Unauthorized).

5. Dans les outils de développement du navigateur, quel onglet permet de voir les requêtes HTTP envoyées par la page ?

a) Elements   b) Network   c) Console   d) Sources

Voir la réponse

b) Network, qui liste toutes les requêtes avec leur méthode, leur URL, leurs données et leur statut.

6. Avec fetch(), quelle option permet de choisir la méthode HTTP ?

a) type   b) method   c) verb   d) action

Voir la réponse

b) method, par exemple fetch('/api/salles', { method: 'PATCH' }).

7. Quelle est la valeur de response.ok si le serveur répond avec le code 404 ?

a) true   b) false   c) 404   d) undefined

Voir la réponse

b) false, car ok n'est vrai que pour les codes 2xx.

B. Questions d'explication (exemples)

E1. Pourquoi ne met-on normalement pas de données dans le corps (body) d'une requête GET ? Donnez un exemple de l'alternative.

Voir une réponse attendue

Une requête GET sert à lire une ressource, et le corps d'un GET n'est pas prévu par le protocole (il est ignoré ou mal supporté). On met les données dans la query string, par exemple GET /api/chansons?artiste=Beatles.

E2. Pourquoi faut-il vérifier response.ok avant await response.json() ? Qu'arrive-t-il si le serveur répond 404 avec une page d'erreur HTML ?

Voir une réponse attendue

Si la réponse n'est pas du JSON valide, response.json() échoue et génère une erreur. La vérification de ok permet de traiter l'échec proprement, sans essayer d'extraire des données qui n'existent pas.

E3. Expliquez la différence entre npm start et npm run dev, en lien avec le fichier package.json.

Voir une réponse attendue

Les deux lisent la section scripts. npm start lance node server.js, pour la production. npm run dev lance nodemon server.js, qui redémarre le serveur à chaque modification, pour le développement.

C. Problème de programmation en plusieurs étapes (exemple)

Étape 1 — Couche de données (model/chansons.js). Tableau privé de chansons (chaînes de caractères). Exportez getChansons(), addChanson(titre), updateChanson(index, titre) et deleteChanson(index).

Étape 2 — Routes (server.js). GET /api/chansons (200), POST /api/chansons avec le titre dans le corps (201), PUT /api/chansons avec l'index et le titre dans le corps (200), DELETE /api/chansons avec l'index dans le corps (200).

Étape 3 — Partie créative. Ajoutez une route utile pour une liste de chansons, expliquez-la en une phrase et donnez le code de statut retourné.

Voir la solution de référence (étapes 1 et 2) 
// model/chansons.js
let chansons = [];

export function getChansons() {
    return chansons;
}

export function addChanson(titre) {
    chansons.push(titre);
}

export function updateChanson(index, titre) {
    chansons[index] = titre;
}

export function deleteChanson(index) {
    chansons.splice(index, 1);
}

// server.js
import 'dotenv/config';
import express, { json } from 'express';
import { getChansons, addChanson, updateChanson, deleteChanson } from './model/chansons.js';

const app = express();
app.use(json());

app.get('/api/chansons', (request, response) => {
    response.status(200).json(getChansons());
});

app.post('/api/chansons', (request, response) => {
    addChanson(request.body.titre);
    response.status(201).end();
});

app.put('/api/chansons', (request, response) => {
    updateChanson(request.body.index, request.body.titre);
    response.status(200).end();
});

app.delete('/api/chansons', (request, response) => {
    deleteChanson(request.body.index);
    response.status(200).end();
});

app.listen(process.env.PORT);

D. Tester une API avec Thunder Client ou Postman (exemple)

Vous avez une route DELETE /api/chansons qui supprime une chanson selon sa position (index), envoyée dans le corps JSON. Expliquez comment vous la testeriez dans Thunder Client, étape par étape : l'URL, la méthode, le corps JSON, et le code de statut attendu. Comment vérifieriez-vous que la suppression a bien fonctionné ?

Voir une réponse attendue
  1. URL : http://localhost:PORT/api/chansons (le port défini dans .env).
  2. Méthode : DELETE.
  3. Corps : onglet Body, type JSON, avec { "index": 0 }.
  4. Statut attendu : 200.
  5. Vérification : envoyer un GET /api/chansons et contrôler que la chanson de la position 0 n'est plus dans la liste.

A. QCM (exemples)

1. Que retourne une fonction async qui n'a aucune instruction return ?

a) Une promesse résolue avec undefined   b) Rien   c) Une erreur   d) Un callback

Voir la réponse

a) Une fonction async retourne toujours une promesse, même si elle ne retourne rien.

2. Dans un projet Express, quel dossier contient les fichiers statiques servis avec express.static('public') ?

a) src   b) public   c) model   d) node_modules

Voir la réponse

b) public, par convention dans ce cours.

3. Pourquoi installe-t-on nodemon avec l'option -D ?

a) Parce que c'est une dépendance de développement, inutile en production.   b) Pour le déployer.   c) Pour l'ignorer dans Git.   d) Pour changer le port.

Voir la réponse

a) nodemon ne sert qu'à développer. On ne l'utilise pas en production.

4. Dans l'URL /api/films/12, que représente 12 si la route est définie comme /api/films/:id ?

a) Un fragment   b) Une query string   c) Un paramètre de route (params)   d) Un en-tête

Voir la réponse

c) Une donnée placée dans le chemin de la route, lue avec request.params.id.

5. Quel code de statut est normalement retourné après une suppression réussie avec une réponse vide ?

a) 200   b) 201   c) 404   d) 500

Voir la réponse

a) 200, avec response.status(200).end().

6. Dans fetch(), quelle option sert à ajouter des données dans le corps de la requête ?

a) body   b) data   c) payload   d) send

Voir la réponse

a) body, qui doit être une chaîne de caractères (par exemple JSON.stringify(data)).

7. Quelle commande crée un fichier package.json dans un nouveau dossier de projet ?

a) npm init   b) npm start   c) node init   d) npm update

Voir la réponse

a) npm init, qui pose quelques questions et crée le fichier.

B. Questions d'explication (exemples)

E1. Expliquez pourquoi setTimeout(() => console.log('B'), 0) n'arrête pas le reste du programme.

Voir une réponse attendue

setTimeout enregistre la fonction pour plus tard et laisse le programme continuer. Le code qui suit s'exécute donc en premier, et le callback n'est appelé qu'après, quand le programme a fini son travail en cours.

E2. Quelle différence y a-t-il entre le code 200 et le code 201 quand on répond à une requête ? Donnez un exemple de chaque.

Voir une réponse attendue

200 indique un succès général, par exemple une lecture ou une suppression réussie. 201 indique qu'une nouvelle ressource a été créée, par exemple après un POST qui ajoute un film.

E3. Expliquez la différence entre response.status et response.ok dans un fetch().

Voir une réponse attendue

response.status donne le code exact (par exemple 404). response.ok est un booléen : vrai si le code est entre 200 et 299, faux sinon.
